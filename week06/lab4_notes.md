# Lab 4 Notes: Referential Integrity

When I tried to delete the "Library and Information Science" department, MySQL gave me **Error 1451: Cannot delete or update a parent row: a foreign key constraint fails**. MySQL refuses because the Student table has a foreign key (`dept_id`) that points to the Department table, and a student (Transfer Student) was still assigned to that department. If MySQL allowed the delete, that student would be left pointing to a department that no longer exists, which would break the link between the two tables. I fixed it the correct way by first running an `UPDATE` to move Transfer Student to the Software Engineering department, and then running the `DELETE` again, which succeeded. The student was moved rather than lost, and the Department table went back to 5 departments. Another way to fix it would be to define the foreign key with `ON DELETE CASCADE`, so deleting a department automatically deletes its students, or with `ON DELETE SET NULL`, which sets the students' `dept_id` to NULL (this only works if the column allows NULL). I could also have deleted the dependent student first. I chose to reassign the student because it keeps the data safe, whereas `CASCADE` could delete many records by accident.
